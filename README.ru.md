# rucert

[English version](README.md)

Консольный визард для macOS и Windows, который настраивает выбранные Chromium-браузеры доверять
Russian Trusted Root CA (сертификат Минцифры, https://www.gosuslugi.ru/crt) **только для
фиксированного списка доменов** и не добавляет сертификат в системное хранилище.

## Зачем

Сертификат Russian Trusted Root CA, установленный в системное хранилище, может подтверждать
_любой_ сайт во _всех_ приложениях. rucert ограничивает доверие:

- только выбранными браузерами;
- только перечисленными доменами и их поддоменами (например, `gosuslugi.ru` покрывает
  `www.gosuslugi.ru` и `esia.gosuslugi.ru`);
- системное хранилище (связка ключей macOS, хранилище сертификатов Windows) не меняется.

Сертификат этого УЦ для любого другого домена браузер отвергнет. Это защищает от MITM через
этот УЦ за пределами разрешённых доменов.

## Как это работает

Политика браузера
[`CACertificatesWithConstraints`](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/cacertificateswithconstraints)
добавляет корневой сертификат с ограничением `permitted_dns_names`. Промежуточные сертификаты
передаются в
[`CAHintCertificates`](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/cahintcertificates):
сами по себе они не становятся доверенными и нужны только для построения цепочки, если сервер
не прислал промежуточный сертификат. Поэтому любая цепочка всё равно заканчивается на корневом
сертификате с ограничением доменов. Обе политики бывают только обязательными:

- **macOS**: они доставляются профилем конфигурации (`.mobileconfig`) с принудительными
  настройками. rucert генерирует профиль и открывает его, а установку вы подтверждаете в
  Системных настройках: без MDM macOS не позволяет ставить профили молча.
- **Windows**: они записываются в `HKEY_LOCAL_MACHINE\SOFTWARE\Policies\<производитель>\<браузер>`.
  Сам визард работает без прав администратора; с повышенными правами выполняется только запись
  в реестр, после подтверждения запроса UAC.

Поддерживаемые браузеры:

| Браузер        | Домен настроек macOS       | Ключ политик Windows                    |
| -------------- | -------------------------- | --------------------------------------- |
| Google Chrome  | `com.google.Chrome`        | `SOFTWARE\Policies\Google\Chrome`       |
| Microsoft Edge | `com.microsoft.Edge`       | `SOFTWARE\Policies\Microsoft\Edge`      |
| Brave          | `com.brave.Browser`        | `SOFTWARE\Policies\BraveSoftware\Brave` |
| Brave Origin   | `com.brave.Browser.origin` | `SOFTWARE\Policies\BraveSoftware\Brave` |

На Windows Brave и отдельный Brave Origin читают один и тот же ключ политик, поэтому визард
показывает их одним пунктом «Brave / Brave Origin».

Версия браузера должна поддерживать эти политики. После установки они видны на
`chrome://policy` / `edge://policy` / `brave://policy`.

Safari не поддерживается. У него нет собственного хранилища сертификатов и политик: он доверяет
только системному хранилищу macOS, а сертификату оттуда доверяют все приложения. Это
противоречит цели доверять УЦ только в выбранных браузерах.

Встроенные сертификаты:

| Сертификат                    | Роль                                     | SHA-256                                                                                           |
| ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Russian Trusted Root CA       | корневой, только для разрешённых доменов | `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` |
| Russian Trusted Sub CA (2022) | подсказка для построения цепочки         | `BB:BD:E2:10:3E:79:0B:99:9E:C6:2B:D0:3C:F6:25:A5:A2:E7:C3:16:E1:0A:FE:6A:49:0E:ED:EA:D8:B3:FD:9B` |
| Russian Trusted Sub CA (2024) | подсказка для построения цепочки         | `21:55:78:50:36:C9:00:DB:B5:F1:BB:2A:15:69:C8:0C:55:59:5B:D6:BF:94:86:7A:29:BB:DD:BC:7D:88:A3:F2` |

## Установка

Скачайте архив для своей системы из [Releases](https://github.com/dgavrilov/rucert/releases).

### macOS

Возьмите `rucert-<версия>-macos-arm64.tar.gz` для Apple Silicon или `-x86_64` для Intel.
Распакуйте его и снимите атрибут карантина (бинарник не нотаризован):

```sh
tar -xzf rucert-*-macos-*.tar.gz
xattr -d com.apple.quarantine rucert
./rucert
```

### Windows

Распакуйте `rucert-<версия>-windows-x86_64.zip` (или `-arm64`) и запустите `rucert.exe` из
консоли. Бинарник не подписан, поэтому SmartScreen может предупредить о нём: выберите
**Подробнее → Выполнить в любом случае**.

В Windows Terminal интерфейс отображается полностью. В классической консоли (`cmd.exe` или
PowerShell вне Windows Terminal) визард переходит на ASCII-символы.

## Использование

При первом запуске визард спрашивает язык интерфейса (русский или английский, по умолчанию по
системной локали) и запоминает выбор. Главное меню:

- **Статус**: найденные браузеры, применённые политики, встроенные сертификаты.
- **Установить или обновить**: выбор браузеров, просмотр доменов, затем
  - macOS: подтверждение профиля в Системные настройки → Основные → Управление устройством
    (macOS 13-14: Конфиденциальность и безопасность → Профили);
  - Windows: подтверждение запроса UAC.

  Затем визард проверяет, что политика применилась. Повторная установка заменяет предыдущие
  политики, в том числе убирает их из браузеров, которые больше не выбраны; выбранные браузеры
  запоминаются.

- **Управление доменами**: добавить или удалить свои домены поверх основного списка.
  Wildcard, домены верхнего уровня и IP-адреса отклоняются, кириллические домены переводятся в
  punycode. Если при выходе из этого меню список изменился, политики применяются заново к
  запомненным браузерам.
- **Проверить обновления списка доменов**: загружает `assets/constraints.json` из этого
  репозитория, показывает добавленные и удалённые домены и применяет список только после
  подтверждения; затем политики применяются заново так же.
- **Удалить**:
  - macOS: выполняет `sudo profiles remove -identifier io.github.dgavrilov.rucert`; профиль
    также можно удалить в Системных настройках;
  - Windows: после запроса UAC удаляет из реестра значения политик rucert; остальные политики
    не трогает.
- **Сменить язык**.

На macOS, если ту же политику для браузера задаёт другой профиль (например, установленный ранее
вручную), удалите его: macOS не определяет, какой из двух конфликтующих профилей победит.

Настройки хранятся в `~/Library/Application Support/rucert/settings.json` на macOS и в
`%APPDATA%\rucert\settings.json` на Windows.

## Если сертификат уже установлен вручную

Импортировать сертификаты вручную не нужно: их добавляют политики. Russian Trusted Root CA,
установленный вручную, доверен для любых сайтов, и ограничение по доменам на него не
распространяется. Если он был установлен раньше, например по инструкции с Госуслуг, и вне
браузеров не нужен, его можно удалить:

- из связки ключей macOS («Связка ключей», связки «вход» и «Система»);
- из хранилища Windows («Доверенные корневые центры сертификации» в `certmgr.msc` и
  `certlm.msc`);
- из менеджера сертификатов браузера (`chrome://certificate-manager`, «Установленные вами»).

Визард предупреждает в **Статусе** и после установки, если сертификату доверяет система.
Сертификаты, импортированные в менеджер сертификатов браузера, обнаружить нельзя, проверьте их
сами.

## Список доменов

```json

```
